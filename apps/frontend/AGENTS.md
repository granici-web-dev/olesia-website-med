# apps/frontend — the public site

The block above is generated by `next dev`; keep it. Everything below is ours. General
rules: `../../AGENTS.md`. Responsive work uses the `tailwind-responsive-design` skill;
visual work uses `impeccable`. `origin/` is the reference design and is never edited.

## Shape

Next.js 16 App Router, React 19, `next-intl` for the shared frame, Tailwind v4 + CSS
Modules. Pages are server components that read the API through `lib/api.ts`; the few
interactive pieces are leaf client components with `useState`. No state library, no
client data-fetching library. `app/[locale]/` holds the routes, `components/sections/`
the page sections, `components/layout/` Nav and Footer, `components/ui/` primitives,
`lib/` pure helpers with tests.

## Where each string lives (R3 in detail)

**Page copy is authored inline as a ternary on the locale**, all three branches
mandatory and kept in sync by hand:

```tsx
const en = locale === 'en';
const ru = locale === 'ru';
type Bi = { ro: string; en: string; ru: string }; // one shared type, lib/i18n-types
const lc = biFor(locale); // one helper, not a closure per file
```

`i18n/messages/{ro,en,ru}.json` carries the shared frame only: `nav`, `footer` and the
primitives on every page. Adding a key means all three files; parity is checked in
tests. Do not migrate one form into the other.

**API content** is RO and EN with `*Ru` nullable; `loc()` in `lib/api.ts` falls back
RU → RO and treats an empty string as missing. Never invent the client's translation.

## Rules that bite

- **The site holds no copy of what the client edits.** Prices, descriptions, contacts,
  opening hours, the SLA, FAQ, testimonials, articles all come from the API. When the
  API answers empty, the section renders an honest empty state or nothing; it never
  renders a compiled-in value. When the API is unreachable, `getJson` throws and
  `error.tsx` answers; at build time it yields empty so the build survives.
- **No booking fallback.** A service without `calendlySchedulingUrl` renders no button.
  The Calendly widget loads on click, never on mount.
- **Metadata on every page** through `lib/page-metadata.ts`: canonical, hreflang for
  three locales plus `x-default`, Open Graph. `siteUrl()` refuses to build production
  without `NEXT_PUBLIC_SITE_URL`; `API_URL` and `NEXT_PUBLIC_API_URL` are equally
  required, and `next.config.ts` compiles the image host from `API_URL`, so a host change
  means a rebuild.
- **Styling:** Tailwind for layout utilities, CSS Modules for component styles, brand
  tokens as `var(--sage)`, `var(--ink)` … from `globals.css`; no hex in components, no
  `text-[]`/`bg-[]` for brand colours, no inline `style` for what a module rule can do.
  `--sage` is decorative or large text only; body text and status use `--sage-text`.
  Focus rings are opaque; no `outline-none` without a visible replacement.
- **Images:** `next/image` with `alt` and `sizes`; assets under `public/assets/`; nothing
  above ~300 KB without a reason. Three `<img>` in articles remain until the API host is
  stable (`remotePatterns` is compile-time).
- **Components:** named exports, `'use client'` only where hooks or browser APIs are
  used, file order imports → constants → component, `PascalCase.tsx` + `.module.css`.
- **Privacy:** third-party scripts load only after consent (cookie banner) or on click
  (Calendly, YouTube, Facebook). Forms send `x-captcha-token` when the key exists, carry a
  honeypot, cap lengths to the API's limits, and map API codes through
  `lib/form-errors.ts` so 429 and captcha failures read differently from "try again".
  `/incarcare/[token]` and `/payment/*` are `noindex` and `no-referrer`.
- **CSP is Report-Only** for now; reports go to `app/api/csp-report/route.ts`.

## Tests

Vitest, `vitest.config.mts`, `lib/` only: prices, SLA, form errors, calendly URLs,
metadata helpers, `getJson`. Run: `pnpm nx test @olesia/frontend`. The Playwright smoke
path lives in `apps/frontend-e2e` and runs by hand (`TESTING.md`).
