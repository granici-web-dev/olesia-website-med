## Где мы (2026-09-16)

Три приложения живые и проверенные. Программа аудита A1–A13 пройдена целиком за
10–12 сентября: сайт, API по модулям, бэк-офис, инфраструктура, зависимости,
визуальный проход. 534 юнит-теста на трёх раннерах плюс один сквозной сценарий
Playwright. Чекаут maib продаёт EXPRESS, меню, протоколы и материалы, проверен в
песочнице. Прод-стек с Caddy, бэкапами, `/health` и Sentry собран и проверен на
ноутбуке. Полный аудит: `docs/audit-2026-09-10.md`.

Всё, что можно сделать без клиента, сделано. Дальше работа зависит от её
ответов.

**Прод починен 2026-09-16.** На Vercel заданы `NEXT_PUBLIC_SITE_URL`, `API_URL`,
`NEXT_PUBLIC_API_URL`; API-переменные смотрят на туннель cloudflared, поэтому при
каждом его перезапуске адрес меняется и две переменные надо переставить
(`vercel env rm` + `vercel env add … --visibility config --no-sensitive`), затем
`vercel redeploy <последний деплой>`. Пока туннель мёртв, сайт честно показывает
«недоступно». Постоянный адрес появится с хостингом клиента.

### 18. `[ ]` Группа C: цены и названия меню и протоколов из бэк-офиса

Решение Сергея 2026-09-16 по 8c: каталог остаётся кодом, новые услуги клиент сама
не добавляет, у новой услуги всё равно своя страница и свой сценарий. Редактировать
существующее она должна целиком, а пять товаров группы C (меню 7/14/30 дней, два
протокола, 28–98 €) до сих пор лежат в `DELIVERABLE_CATALOG` в `packages/shared`:
их цену и название с сайта не поменять. Читают его API (`leads`, `deliverable-orders`),
сайт (`/pricing`, `lib/deliverable-content.ts`) и бэк-офис (форма заказа).

Команда: `/rigorous shape` → утверждение → `craft`. Коды пяти товаров остаются enum,
цена и названия на трёх языках переезжают в базу и редактируются в бэк-офисе; API
штампует цену в заказ из базы, как сейчас из константы; сайт и бэк-офис читают
каталог из API; сид переносит пять записей. Критерий: смена цены меню в бэк-офисе
видна на `/pricing` и в новом заказе без деплоя; 534 теста плюс новые зелёные.

## Как вести файл

Шаг закрывается, когда критерий проверен и изменения закоммичены: статус `[x]`,
хэш, одна строка итога. Подробный отчёт и решения по ходу уходят в
`docs/plan-log.md`, не сюда. Файл держится короче 150 строк: новая сессия читает
его целиком, и каждая лишняя строка платится в каждой сессии.
