## 1. Вердикт

Проект в хорошей инженерной форме и не готов к запуску. Эти два утверждения не
противоречат друг другу.

**Хорошая форма.** Три приложения живые, архитектура чистая, границы валидируются,
логи без PII, секреты не текут, миграции применяются, CI проверяет типы, сборки,
миграции и с сегодняшнего дня тесты. Платёжный реестр, загрузка анализов и
авторизация прошли аудит и укреплены. Прод-стек поднимается одной командой.

**Не готов.** Сайт публикует выдуманные медицинские статьи и меню под именем
врача. Редактор контента имеет доступ к планам лечения. Платные гайды раздаются
бесплатно. Пациенту не отправляется ни одно письмо. Бэк-офис показывает «записей
нет» там, где упал запрос. Мониторинга нет вообще. И ни одна из этих проблем не
зависит от клиента: это наша работа, шаги 10–16 плана.

Вне нашего контроля: хостинг, домен, юрлицо, Calendly, график, SMTP, контент.
Без них сайт не запустится, даже если код будет идеален.

## 2. Что построено

**Публичный сайт** (`apps/frontend`, Next.js 16, три локали): 20 маршрутов,
главная, услуги, пять посадочных услуг, тарифы, библиотека, статьи, меню, FAQ,
о враче, медиа, контакты, юридические страницы, загрузка анализов по токену.
Формы: контакт, EXPRESS, мониторинг, заказ deliverable, рассылка, email-гейт
библиотеки. Cookie-баннер самописный, аналитика по env, Calendly-виджет.

**API** (`apps/api`, NestJS 11, Prisma 7, Postgres): 27 модулей. Контент (услуги,
блог, о враче, контакты, FAQ, отзывы, медиа, материалы, site-media, рабочие
часы), операции (записи с вебхуком Calendly, подписки, EXPRESS, заказы, сообщения,
пациенты с историей и документами, загрузка анализов по токену, платежи maib с
реестром и рефандами), auth с 2FA и сессиями, почта, хранилище, крон-задачи.

**Бэк-офис** (`apps/back-office`, React + Vite, только румынский): 24 страницы,
каждый модуль API имеет страницу, ни одной фичи только на моках. Форма смены
пароля, 2FA, страница платежей с рефандом, панель загрузок в карточке записи.

**Инфраструктура**: Vercel для сайта, `docker-compose.prod.yml` с Postgres, API,
Caddy (TLS + бэк-офис), бэкапами по расписанию и профилем restore. Prod-safe seed.
Runbook на день деплоя. GitHub Actions CI, Dependabot.

## 4. Состояние по зонам

Оценка: ✅ в порядке · 🟡 работает, есть долг · 🔴 блокирует запуск или опасно ·
⚪ не оценивалось.

### 4.1 Архитектура и стандарты — ✅

Монорепо Nx с тремя приложениями и общим пакетом DTO. Один модуль на домен в
API, зеркальная структура в бэк-офисе. Валидация по границам, внутренний код
доверяет типам, ноль `any`, пять `as unknown as` с причинами. Комментарии несут
провенанс решений, это домашний стиль и он записан как правило. Собственная CMS
вместо сторонней, решение обосновано. Долг: зависимости трёх приложений в
корневом манифесте (API выделен сегодня, сайт и бэк-офис нет); ESLint отсутствует
осознанно.

### 4.2 API: платежи, загрузки, авторизация — ✅ после сегодняшнего укрепления

Что осталось открытым с записью: хэширование upload-токена и шифрование
TOTP-секрета (обе про «что лежит в дампе», решаются шифрованием бэкапов при
переезде off-site); `Number()` в денежной арифметике; последовательный
`reconcileStale`; резерв рефанда, зависший при падении процесса между записью и
ответом банка; callback банка ни разу не приходил, потому что нет публичного
адреса.

### 4.3 API: остальные модули — 🔴 четыре high

- Редактор контента (`editor`) под `@Roles(admin, editor)` на записях и заказах:
  читает и пишет план лечения, скачивает рецепт, удаляет заказ с каскадным
  стиранием анализов. `patients` и `uploads` уже только `admin`.
- `toMaterialDto` отдаёт `fileUrl` платных материалов на публичном `/uploads`.
- Лид Calendly без email становится `''`, `Patient.email` уникален, `fromLead`
  делает upsert: все безымянные лиды сливаются в одного пациента.
- `LEADS_NOTIFY_EMAIL` по умолчанию личный Gmail разработчика.

Medium: `RolesGuard` без метаданных пропускает любого аутентифицированного;
`/services` и `/contacts` без фильтра `active`, `calendlyEventTypeUri` публичен;
GDPR-стирание не трогает `Payment`; синглтоны About и WorkingHours создаются в
гонке; квота видеозвонков read-then-write; гонки слагов дают 500; timezone
рабочих часов без валидации роняет приём EXPRESS; вебхук Calendly без окна
реплея; неизвестный `event_type` только в лог; `@Body('title')` мимо DTO;
`RECAPTCHA_SECRET` пустой молча выключает капчу; `PRIVATE_UPLOADS_DIR` без env
это `cwd()`.

Что сделано хорошо: строгая глобальная валидация, вебхук fail-closed, нет path
traversal, приватные файлы отделены, логи без PII во всех модулях, sharp
пересжимает в WebP и снимает EXIF.

### 4.4 Почта и уведомления — 🔴

Пациенту не отправляется ничего. Ответ на EXPRESS пишется в базу и всё, при том
что интейк обещает ответ за час. Подтверждение записи и prep-инструкции это
`logger.log` с `TODO(email)`. `MailService` глобален, шлёт только уведомления
врачу о лидах, `sendToClient` никем не вызывается. SMTP не настроен, провайдер
не выбран (предложен Brevo), ящик на домене отсутствует. Это одновременно наша
работа (одна точка отправки, шаблоны RO/EN/RU) и блокер клиента (SMTP).

### 4.5 Публичный сайт — 🔴 по содержанию, 🟡 по технике

Правда:

- `/articles` жёстко на `USE_LIVE = false`, восемь выдуманных статей с
  медицинскими советами публикуются под подписью врача даже при живом API.
- `/menus` без API вовсе, восемь выдуманных меню, `sitemap.ts` отдаёт их Google.
- «12+ ani» и «1.400+ familii» в hero всех локалей это статичный JSON, клиент
  не подтверждала.
- Юридические страницы честно показывают баннер «черновик» всем посетителям.
- 23 кнопки записи ведут на тестовый Calendly, где четыре из пяти событий
  неактивны; это состояние аккаунта, чинится платным тарифом клиента.

Приватность:

- Виджет Calendly грузится при монтировании на каждой странице через Nav и
  Footer, до любого согласия, два запроса к `assets.calendly.com` на просмотр.
- Email-гейт библиотеки берёт адрес под галочкой согласия и выбрасывает:
  `subscribe()` без `await` сразу возвращает `disabled`.
- reCAPTCHA не настроена, три модальные формы без honeypot.
- Cookie-баннер самописный, три равные кнопки, журнала согласий нет.

SEO: ни одной `alternates.languages`, ни одного `canonical`, ни одного
`openGraph`, нет `metadataBase`, favicon и OG-картинки; `/pricing`, `/services` и
каждая статья наследуют заголовок главной; `siteUrl()` без env даёт `localhost`.

Производительность: 38 МБ в `public/assets` (три MP4 по 7,7 МБ, PNG 7 МБ,
портрет 4,6 МБ), три `<img>` вместо `next/image`, шрифты без кириллицы для
русской версии. Lighthouse не запускался.

Доступность: в целом сильно (метки, `aria-invalid`, reduced-motion в шести
местах, ошибки не только цветом). Мелочи: `<h3>` среди `<h2>` на главной, фокус
только цветом в форме загрузки, обложка статьи с `alt=""`.

Заголовки безопасности: nosniff, X-Frame-Options, Referrer-Policy,
Permissions-Policy, HSTS есть. CSP осознанно отложен до финализации аналитики.

i18n: 115 ключей JSON в паритете; один дефект, `serviceTag()` без ветки RU.
Основной копирайт в инлайн-тернарниках по 38 файлам, все три ветки на месте.

Мёртвое: `PainPoints.tsx`, `lib/query-client.ts`, `store/ui.store.ts`,
`@tanstack/react-query` и `zustand` не используются нигде на сайте.

Поведение при мёртвом API: честное на главной, тарифах, услугах, библиотеке;
константный фолбэк на FAQ и посадочных (ссылки Calendly); плохое на статьях и
меню.

Визуальный дизайн и UX: ⚪ не оценивались в этом аудите, это отдельная работа
через `impeccable` с браузером.

### 4.6 Бэк-офис — 🟡 с двумя опасными состояниями

Хорошо: каждая фича на реальном HTTP, единый паттерн ошибка/загрузка/пусто на 19
из 24 страниц, мутации с тостами и блокировкой кнопок, access-токен в памяти,
refresh в httpOnly cookie с single-flight, скачивания приватных файлов через
аутентифицированный blob, диакритика корректна во всех 722 ключах, dev-tools
выпадают из прод-бандла, гейт смены пароля непроходим.

Опасно:

- `patient-detail.tsx` не проверяет `timelineQuery.isError`: упавший запрос
  рендерится как «Nu există anamneze».
- Все девять списков обрезаны на 200, `total` выбрасывается, пагинации нет;
  поиск пациентов на клиенте по полной выгрузке PII.
- Удаление документа пациента и отзыв ссылки одним кликом без диалога.

Плохо: `queryClient.clear()` не вызывается при logout; истечение сессии
выбрасывает на пустой логин без объяснения; `/pacienti` и панель загрузок видны
редактору, API отвечает 403 общей ошибкой; `about.tsx` и `blog-editor.tsx` при
ошибке показывают пустой редактор с живой кнопкой сохранения; три blob-скачивания
мимо refresh-обёртки; кнопка «Ai uitat parola?» без обработчика; поиск в шапке и
колокольчик без обработчиков, карточка «Activitate» никогда не заполнится; нет
кнопок для сброса 2FA другому пользователю, ссылки загрузки для заказа,
переименования категории, принудительной синхронизации Calendly; `asList`
девять копий, `ConfirmAction` две; тестов ноль, Vitest подключён без конфига.

### 4.8 Наблюдаемость — 🔴 отсутствует

## 6. Что сделано плохо или недоделано

Не уязвимости, а места, где качество ниже остального проекта.

- **Уведомления пациенту не существуют** при готовом почтовом сервисе. Самая
  большая функциональная дыра: обещание «ответ за час» ничем не подкреплено.
- **Каталог услуг не data-driven** вопреки требованию брифа §10: код услуги это
  enum из семи значений, новая услуга это правка трёх приложений. Группа C
  (меню, протоколы) не редактируется вообще. Шаг 8c, ждёт решения.
- **Инлайн-копирайт** в 38 файлах на три языка: правило переписано под практику,
  но клиент такие тексты сама не поправит.
- **Бэк-офис без пагинации** и с клиентским поиском: терпимо на старте, ломается
  на третьей сотне пациентов.
- **Fake-элементы в интерфейсе**: поиск в шапке, колокольчик, «Activitate»,
  «Ai uitat parola?», два disabled пункта меню. Выглядит как функциональность,
  которой нет.
- **Образ API 1 ГБ** из-за CLI Prisma ради одной команды.
- **`/health` формальный**, мониторинга нет.
- **Медиа-активы** сайта не оптимизированы: 38 МБ.
- **Шрифты без кириллицы** при русской версии как полноценной локали.
- **Два пути уведомлений** в коде (`MailService` и `notifications.service.ts`),
  не связанных друг с другом.
- **Дублирование** в бэк-офисе (`asList` × 9, `ConfirmAction` × 2), мёртвые
  зависимости на сайте (`react-query`, `zustand`).
- **Тесты неравномерные**: 39 на платежи и ноль на бэк-офис.
